Вариант 6. Репертуар театра и продажа билетов.

В приложение добавлены регистрация, вход и разграничение доступа. Данные спектаклей, залов, показов, пользователей и билетов хранятся в базе.

## Пользователи и доступ

Учебный вход: логин `admin`, пароль `admin`. Перед первым запуском скопировать `.env.example` в `.env`.

У пользователя есть имя, логин, пароль, роль и признак активности. Пароль хранится в виде хеша BCrypt и не возвращается в ответах.

- Покупатель (USER) смотрит репертуар, создаёт брони, покупает и возвращает свои билеты. Чужие билеты ему недоступны.
- Администратор (ADMIN) управляет всеми записями, ролями и блокировкой пользователей, отменяет и завершает показы.

При регистрации создаётся только покупатель. Заблокированный пользователь не может войти. Удалить, заблокировать или понизить последнего активного администратора нельзя.

## Операции

Сохранены просмотр, создание, изменение и удаление записей, а также пять операций:

1. Бронирование соседних свободных мест одной группой.
2. Покупка забронированного билета.
3. Возврат купленного билета до начала показа.
4. Отмена будущего показа с отменой броней и возвратом оплаты.
5. Завершение показа с обновлением статусов билетов.

Вход выполняется через HTTP Basic. Для запросов, изменяющих данные, нужен CSRF-токен, который выдаёт `/api/auth/csrf`. Регистрация доступна по `/api/auth/register`, свои данные по `/api/auth/me`.

Ошибки входа возвращают 401, недостаток прав или неверный CSRF-токен 403, нарушение бизнес-правил 409. Коллекция запросов проверяет успешные действия и отказы для разных пользователей.
